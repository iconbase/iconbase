# 下架申请(takedown)

iconbase 收录了不少**别人的商标图形** —— 品牌标识、云厂商标识、emoji。
著作权那层我们逐条记着(见 [`NOTICE.md`](../NOTICE.md) 与 [`si-manifest.json`](../si-manifest.json)),
商标权归各个品牌方。

**如果你是商标权人(或拿到授权的人),而我们收录的某个标识你希望撤下 —— 请开一个 issue。**

## 怎么提

在 [`iconbase/iconbase`](https://github.com/iconbase/iconbase/issues) 开 issue,
标题写 `[takedown] <品牌名>`,正文里说明:

1. **你是谁** —— 公司/机构、官网链接;或你受权代理的说明
2. **要撤哪一枚** —— 键名(如 `si:example`),或图标文件路径
3. **依据** —— 品牌规范页/政策页的链接;或商标注册号
4. **你的诉求** —— 下架 / 换成官方素材 / 只在本仓之外的场合不用

不用写法律文书 —— **能证明你是权利人、或者说明它违反了你的使用条款,就够我们动手**。

## 我们怎么处理

| 步骤 | 承诺 |
| --- | --- |
| 1. 核实 | 确认身份与依据。**不问法务意见** —— 只看你给的政策页与条款 |
| 2. 下架 | 从数据仓移除该图标与它的索引条目;从 sprite 里去掉;边缘缓存随之失效 |
| 3. 同步 | 数据仓的提交 → 服务仓取数重建 → 线上生效 |
| 4. 回执 | 在那个 issue 里回复,附上移除的提交号 |

**目标:核实后 72 小时内下架,发 issue 通知。** 若你的诉求更急(比如涉及误导或安全),
在 issue 里说明,我们在 24 小时内先下架、后核实。

## 我们不做什么

- **不提供法律意见** —— 我们只按你给的条款和依据执行
- **不替你追责** —— 如果第三方从我们这里拿走素材做了别的事,那是他们的事
- **不批量通知** —— 逐个处理,谁提的谁回

## 已经下架过的

下架记录在数据仓的提交历史里(`git log --diff-filter=D -- icons/`)。
上游品牌方自己撤下的(Simple Icons 的移除机制),我们同步跟着撤 ——
那些在 [`nonindex.json`](nonindex.json) 里,标着「上游撤下」。
